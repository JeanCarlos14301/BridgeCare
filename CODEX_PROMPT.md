## Phase B — write to `docs/backlog.md`, do NOT implement

Build one complete vertical slice before expanding.

- Flow: preloaded synthetic case → text extraction by page → model returns JSON with citations → backend validation → human review → printable approved patient view.
- Case states: `received → processing → needs_review → approved | rejected`; `processing → failed`. The server owns all transitions; it never accepts `approved` from the model or a request body. Any edit or reprocessing after approval returns to `needs_review` and invalidates the previous output.
- Versioned JSON per revision: `case_id, revision_id, content_hash, status, source_documents, extracted_fields, patient_draft, uncertainties, citations, provider_mode, timings, review`.
- Every field has `evidence_state`: `supported | missing | ambiguous | conflicting` (supported = documentary support only, not clinical correctness). No model-invented confidence percentages.
- Medication fields (name, dose, unit, route, frequency, duration) are copied verbatim; `null` when absent. Never infer dates, doses, durations, diagnoses or urgency. Never compute schedules.
- The patient-view medication table is rendered deterministically from validated fields, never from model-generated prose. The model only rewrites non-critical text.
- Every citation references document, page and exact quote; the backend checks the quote exists. Document that this does not prove semantic correctness.
- Invalid schema, insufficient text, timeout, truncation or a detected contradiction block approval.
- Document content is untrusted data: instructions inside it never change prompts, tools or gates.
- Approval is transactional on the current `revision_id + content_hash`. A critical conflict requires a recorded resolution note.
- Endpoints: `GET /fixtures`, `POST /cases/from-fixture`, `POST /cases/upload` (private env only, 5 MB / 10 pages, disabled when `ALLOW_UPLOADS=false`), `GET /cases/{id}`, `POST /cases/{id}/process` (409 if already processing), `PATCH /cases/{id}/draft` (new revision), `POST /cases/{id}/review`, `GET /cases/{id}/patient-view` (409 unless a valid current approval exists), `DELETE /cases/{id}`.
- Access: public visitors only pick fixtures inside an isolated session, no uploads. The reviewer logs in with a server-side password and an HttpOnly session cookie. Authorization is checked per session and case on every endpoint; a UUID alone is not authorization.
- One concurrent processing job per API instance; jobs interrupted by a restart are marked `failed`.
- Six synthetic fixtures first (two clear, one with missing fields, one contradictory, one prompt injection, one provider failure), each with `expected.json`; expand to 12 only if time allows.
- Safety tests: cross-session access, export before approval, approving a stale revision, invalidation after edit, unresolved conflict, non-existent citation, altered dose, prompt injection, timeout, invalid JSON, hidden fallback to mock, public upload blocked.
- Evaluation report with real numbers only (numerator/denominator): critical-field fidelity, supported claims, gate blocks, omissions, manual vs assisted time including review, end-to-end and model latency, cost per case. Never invent accuracy or time savings.
